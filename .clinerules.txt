# Контекст проекта R-PARTNER (Экосистема R-CORE / NEXUS)
Роль пользователя: Руководитель проекта (Product Owner). Он не пишет код руками, а ставит задачи, управляет архитектурой и проверяет результат визуально.
Роль ИИ (Cline): Автономный Senior Developer.

# Правила общения и написания кода
1. Язык общения: Строго русский.
2. Технические термины: Все названия функций (functions), виджетов (widgets), экшенов (actions), переменных и таблиц БД пиши строго латиницей.
3. Код: Пиши только полностью готовый, рабочий код. Никаких заглушек (placeholders) или комментариев вроде "// добавьте код здесь".
4. Алгоритм работы: Делай тестовые прогоны. Не удаляй старый рабочий код, пока не убедишься, что новый функционал работает без ошибок.

# Технический стек (Текущий этап - прототипирование)
- Frontend: HTML5, CSS3, чистый JavaScript (Vanilla JS).
- Стилизация: Tailwind CSS (подключать строго через CDN-ссылку в head, без сборки npm).
- База данных (на будущее): Supabase (Self-hosted).
- Инфраструктура (на будущее): Cloudflare Tunnel, Docker.

# Дизайн-система (UI/UX)
- Тема: Светлая тема (Light Mode).
- Основной фон приложения: Светло-серый (например, #F3F4F6).
- Карточки и нижнее меню: Чисто белый фон (#FFFFFF) с мягкими тенями (shadow) и аккуратным скруглением (rounded).
- Акцентный цвет: Зеленый (использовать для активных элементов, иконок, кнопок и плюсовых сумм).
- Текст: Контрастный (темно-серый или черный для читаемости).
- Юзабилити: Использование быстрых кнопок (Chips) для ввода стандартных значений (например, сумм), адаптивность под мобильные устройства, нижнее меню навигации (Bottom Navigation Bar).

# Безопасность и Архитектура (Multi-tenant)
- Во всех запросах к Supabase в будущем ОБЯЗАТЕЛЕН жесткий фильтр по UUID компании: `eq('company_id', 'твой_uuid')`. Данные разных партнеров не должны пересекаться.
